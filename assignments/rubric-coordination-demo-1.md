# Rubric: Coordination Demo #1

**Total: 15 points** · Graded individually · Accept/Reject with comments · Rejected work may be resubmitted within 1 week

## Criteria

### 1. Thesis Connection (4 pts)
*Does the demo actually test the team's thesis?*

| 4 — Exemplary | 3 — Proficient | 2 — Developing | 0 — Reject |
|---|---|---|---|
| Demo is designed so its outcome directly validates or falsifies the thesis; the demo note states exactly what result would count as evidence for or against | Demo is clearly related to the thesis, but the link is loose — the demo produces relevant output without a stated test condition | Demo touches the thesis domain but mostly demonstrates generic capability; thesis connection is asserted, not demonstrated | Demo does not test the thesis at all — "a beautiful tool that doesn't test the thesis is a reject" |

### 2. Working System (4 pts)
*Does the demo run, and does it do what the team claims?*

| 4 — Exemplary | 3 — Proficient | 2 — Developing | 0 — Reject |
|---|---|---|---|
| Live demo (or walkthrough) runs end-to-end; output is correct, structured triage (item, responder, deadline, contractual risk); failure modes handled or acknowledged honestly | System runs with minor gaps; output structure present but partially incomplete or requires manual patching shown in the demo | System runs only partially or is cherry-picked; claimed functionality not fully demonstrated | No working demo submitted, or the demo does not run |

### 3. Data Provenance (3 pts)
*Is the data real, synthetic, or hybrid — and is that documented?*

| 3 — Exemplary | 2 — Proficient | 1 — Developing | 0 — Reject |
|---|---|---|---|
| Data source documented (real with partner permission, or synthetic); synthetic data includes generation script + justification note explaining why the synthetic corpus is representative of the target correspondence | Data source identified; synthetic script included but justification is thin (no argument for representativeness) | Data source vague; script or justification missing one element | Undocumented data of any kind — undocumented synthetic data is a reject |

### 4. Repo Quality (2 pts)
*Could someone else reproduce this?*

| 2 — Exemplary | 1 — Proficient | 0 — Reject |
|---|---|---|
| Repo contains code, data, all LLM prompts used, and dependencies (README/requirements); a newcomer could run it | Repo mostly complete; one element (e.g., some prompts or a pinned dependency) missing or stale | Repo missing code, prompts, or dependencies such that it is not reproducible |

### 5. Demo Note & Individual Contribution (2 pts)
*Communication and accountability.*

| 2 — Exemplary | 1 — Proficient | 0 — Reject |
|---|---|---|
| Demo note ≤500 words, states what was tested, what happened, and what it means for the thesis; contribution statements present for every team member | Note or contributions present but thin — e.g., missing "what it says about the thesis," or generic contribution labels | Note missing or over-length; contribution statements missing |

## Grading notes

- **Graded individually:** criteria 1–4 are scored on the team artifact but entered per student; criterion 5 is strictly individual. A student whose contribution statement is missing or generic loses criterion-5 points even if the team artifact is strong.
- **Accept/Reject:** an overall score of 11+ with no criterion at 0 is an Accept; any criterion at 0, or total below 11, is a Reject with comments and a 1-week resubmit window.
- **Academic integrity:** undocumented synthetic data or unverifiable "live" demos presented as working systems are integrity violations, not just quality issues.
